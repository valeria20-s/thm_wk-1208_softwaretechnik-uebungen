## 1. Worum es bei dem Projekt geht (Zielsetzung)
Dieses System soll dabei helfen, Termine an der Hochschule einfach zu planen. 
Beispiel: Statt Termine für Sprechstunden per E-Mail zu klären, läuft alles zentral über diese eine Software.

## 2. Wer das System benutzt (Benutzerrollen)
Es gibt verschiedene Gruppen von Menschen, die das System für unterschiedliche Dinge brauchen.
Beispiel:
* Lehrende: Tragen ihre freien Zeiten für Sprechstunden ein.
* Studierende: Suchen sich einen freien Termin aus und buchen ihn.
* Sekretariate: Können alle Termine ansehen, um den Überblick zu behalten.

## 3. Was das System genau tun muss (Funktionen)
Hier wird beschrieben, welche Aufgaben die Software Schritt für Schritt erledigen soll.
Beispiel: Ein Studierender klickt auf einen freien Termin. Das System speichert die Buchung und bietet dem Studierenden sofort eine Kalender-Datei (iCal) zum Herunterladen an.

## 4. Technische Regeln (Vorgaben)
Das sind die technischen Grenzen und Pflichten, an die sich die Programmierer halten müssen.
Beispiel:

| Regel | Was das bedeutet |
|---|---|
| Anmeldung | Die Nutzer müssen sich mit ihrem normalen Hochschulkonto einloggen können. |
| Steuerung | Das System braucht eine Schnittstelle (API), damit später KI-Programme darauf zugreifen können. |
